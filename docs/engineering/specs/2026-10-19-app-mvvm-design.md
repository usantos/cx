# App host: Clean Architecture, SOLID and MVVM

The user explicitly authorizes refactoring the complete app module after the host audit. Preserve public Kotlin/JVM contracts, all existing feature StateFlows/owners, routes, saved state, payloads, persistence, security and visible behavior. The app is the composition root, not a new feature containing every business domain. Existing SPEC.md applies. Preserve all previous uncommitted work; no reset/clean/stage/commit/push/publication.

## Boundaries

Keep Android Application/Activity entry points and the necessary public compatibility surfaces at their old JVM names. Real implementations belong to composition, navigation, presentation, domain, data and integration packages. Root public environment values/enums remain passive compatibility models, with categorized domain aliases; do not duplicate models or rename serialized values. Existing app DI public factory objects retain their signatures while forwarding to the feature owner or actual app composition module. Compatibility must be enumerated and enforced, not a blanket root-package exception.

Presentation owns focused screen/route/component/state/viewmodel files. Business work, loading/error/retry and asynchronous coordination move to Jetpack ViewModels with private MutableStateFlow/read-only StateFlow and viewModelScope. Domain ports/use cases must not import Android, Compose, data, network or auth infrastructure. Data implements persistence and client construction; integration owns Activity/WebView/broadcast/permission/lifecycle/Firebase adapters. Navigation consumes results and performs NavController operations; ViewModels must not hold Activity, View, Context or NavController. Existing core infrastructure and feature domain contracts are reused, with no invented APIs, repositories with no responsibility or empty layers.

## Flows

Campaign: observe existing campaign settings through a domain operation; refresh only while resumed, on the original IO dispatcher and only after security succeeds. Cancel refresh when presentation stops or a newer refresh supersedes it. Keep campaign values/colors and original rendering.

Environment: ViewModel owns pending choice, saving/failure/retry and persisted acknowledgement; keep selected/effective process snapshot distinct. Same/production selection does nothing; authorization cancellation/token clearing precede durable commit. Failure does not apply a new process snapshot. Retain pending choice/commit markers across recreation, reconcile an already active choice without saving twice, rethrow cancellation, and keep process closing in the Android adapter. Dropdown expansion remains local visual state.

Session completion: retain identity capture and stale-session guard, concurrent-request guard, exact business messages/destinations and navigation restoration policies. ViewModel owns verification/loading/error. Navigation consumes a typed, acknowledged result and rechecks the lease before private navigation; loading ends after the result is applied. Keep existing CoreNavigation public state properties for compatibility; do not create competing authoritative copies. Lifecycle/auth foreground notices remain Android integration, with opaque existing markers and original expiry semantics.

Startup/queue: ViewModels own the two-second splash minimum, security preparation/retry, queue status and startup decisions. SDK launch, Activity finishing and broadcasts stay in lifecycle-bound adapters; callbacks dispatch typed events. Preserve the legacy onError pass-through behavior, query flag, HTTPS restriction, broadcast order and capped delay. Existing Onboarding StartupViewModel remains its owner. Rendering-only retry underlay state may stay local to the composition. Mock routes/fixtures remain gated by the existing BuildConfig rules; no new production bypass.

Other app responsibilities: keep application-scoped Firebase work outside screen ViewModels, but separate token retrieval/platform setup from registration/identity checks. Capture the original lease before asynchronous token retrieval, reject stale completion, and preserve callback registration/start idempotence. AppContainer keeps its public constructor/getters and navigation interfaces; move operational work to focused runtime/composition collaborators. Preserve Hilt scopes and provider/client replacement order. Share the campaign mapper through core presentation if needed, retaining the old Home public mapping entry.

## Verification

Capture the actual dirty checkout and compiled API baseline before mutation. Characterize current UI/callback behavior before extraction; pure moves use body/API comparison plus existing tests. New structural guard must fail on the current flat host/direct UI operations, then pass. New ViewModel tests precede implementation and cover cancellation, recreation, retries, stale leases and ordering. Test real state/results, not only dependency call counts. Extend app source ownership, layer direction and MVVM guards with positive/negative fixtures and real Gradle rejection cases. Keep every existing coverage minimum and original protected class family/producer/assertion.

Serialize all Gradle executions and freeze source/build inputs during each run. Use only a fresh task-owned emulator; preserve existing AVDs and native reference APKs. Run App JVM and relevant Android tests, exact Home/animation characterization, full modernCheck/releaseCheck for all flavors, and the five conditional native visual cases without changing assertions or masking failures. One fresh-context review checks this round against its own snapshots. Restore normal debug identity/flag, compare public contracts/protected files, update migration docs and remove only owned temporary resources. Existing physical coordinate/private OAuth/biometric/SSO/queue/provider/signing limitations remain explicitly pending; no credential request or fabricated homologation.

## Decisions

Prefer meaningful domain/presentation/data separation plus focused Android adapters over moving files only. Do not put platform objects into a universal AppViewModel or create app domain/data Gradle children merely to match a sample tree. Existing app module boundaries and feature-owned compiled modules remain; package-level guards enforce the host. Public facades cost a small documented compatibility surface but preserve clients. Inline implementation follows existing authorization and developer autonomy; no redundant staged permission or commit handoff. No unknown requirement blocks read-only exploration or reversible implementation.

## User steering: physical APP → features → CORE ownership

The supplied architecture image supersedes the intermediate app-local layer allocation. APP owns Application/MainActivity, global navigation and initialization/composition only. Feature coordinators/ViewModels/screens/domain/data must compile in their feature modules, and shared network/security/preferences/queue/campaign/session infrastructure in CORE. No app domain/data/presentation/integration implementation packages remain. Necessary public app composition/entry facades retain old contracts; portable old public JVM types can move physically to CORE/features with their original FQNs in an exact compatibility inventory. No aggregate sources or module production dependencies on APP. Existing account includes login/profile flows; existing lottery features remain independent. Add only the justified shared Android security module; do not invent APIs or empty sample modules.

Owners: account owns environment form/commit operations and completion state; onboarding owns startup/queue state; notifications owns Firebase push/device registration; cart Data owns location; tickets Data owns debug fixtures; CORE Domain owns immutable environment/process policy and campaign ports; Data owns campaign repository bridge; Presentation owns shared campaign state/theme; Datastore owns environment storage/confirmed commits; Network owns client construction/replacement; Auth owns generic foreground lease adapters; Queue owns SDK/WebView/broadcast adapter; Security owns Topaz, keyset Firebase/storage, network lifecycle and sanitized inspection. APP passes flavor/endpoints/resources/entry classes as typed configuration/callbacks. Global route eligibility remains APP navigation and is passed to generic lifecycle adapters.
