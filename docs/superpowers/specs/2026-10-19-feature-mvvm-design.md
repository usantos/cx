# Feature-owned MVVM / Clean Architecture

User mandate: all features own their packages, use MVVM, Clean Architecture and SOLID; preserve current observable behavior and integrations per SPEC.md. Work is incremental inside existing dirty codex/migracao-compose checkout. No commits/pushes/reset/staging. Existing authorized code is the baseline, not HEAD.

## Decisions
- All14 Android feature main packages become feature.<name>.presentation with viewmodel, state, coordinator, mapper, route, screen, components, style subpackages as applicable. Split top-level UiState/effects/enums out of ViewModel files before moving. Do not create empty folders or meaningless use cases.
- Feature-owned domain code moves physically to feature/<name>/src/domain/kotlin/.../feature/<name>/domain; feature-owned remote data to src/data/kotlin/.../feature/<name>/data. Existing core:domain and core:data aggregate these source roots. Existing account/cart/betting domain cycles prohibit per-feature domain Gradle modules without redesign. Aggregate preserves internal visibility and inward compile dependencies; it does not claim individual feature isolation.
- Android preference implementations move to owning feature/src/platform/kotlin/.../data/local, compiled only by existing core:preferences. Shared configuration/service/push/network/auth/security/transport infrastructure stays in core, with explicit ownership. Do not place domain/data beneath Android feature src/main, duplicate compilation or add modules/dependencies.
- Home app-owned presentation moves into feature/home/src/host/kotlin/.../presentation/host, compiled by app only. This preserves app resource namespace, app-level integration, visibility/test hosts and flags. Feature Home main still compiles in its Android library; app remains composition root for navigation/session/Results VM. Host presentation must obey the same no-data-access rule. Shared app workflow/navigation/catalog symbols remain app-owned. No manifest identities or resource files/IDs-as-contract are changed.
- Correct real seams: persisted Home order and Shake settings become ViewModel/coordinator state/actions backed by domain use cases, not direct UI repository calls; inject at Hilt root. Keep drag/pager/animation/confirmation-local state in Compose. Account VMs/coordinators consume pure auth/biometric/end-session capabilities; Android intents remain route/platform interactions passed as exchange/resolution operations. Protocol operations and ordering remain unchanged. Source-level package moves are intentional; member signatures/state behavior stay stable except these necessary UI/platform boundaries, updated coherently across consumers/tests.
- Split multi-feature RemoteDataSources.kt contracts by feature, keep shared Retrofit adapter and service mapping in core:data. Do not split by introducing duplicate adapters or requests.

## Preservation and proof
Capture all source/build/script snapshots; original baseline JVM/build then structural architecture RED (flat feature packages) before moves. Token compare every moved body excluding package/import qualification; normalize intentional symbol FQN changes; hand-review substantive seams separately. Update all consumers/tests, resource imports, fully qualified references, coverage source roots and architecture scanning with moved source sets. Keep wire DTOs, JSON keys/enums, preference keys/encodings, URLs, auth pinning, payloads, manifests, Gradle versions and coverage minima unchanged.

Architecture guard rejects flat/misplaced feature files, presentation->data/network, domain->framework/presentation/data, concrete infrastructure in ViewModels and duplicate ownership/source roots. Negative fixtures prove old and newly relocated roots cannot bypass gate. Existing invariants remain enforced, not replaced by looser matching.

Tests cover original observable Home order/Shake behavior and auth cancellation/refresh/post-login/logout sequencing. Run full modernCheck plus releaseCheck three flavors after incremental JVM checks; use an owned temporary AVD and preserve existing instances. Retain special visual oracle failures/private account-device/signing limitations; never claim those external validations complete. Finish with one independent scoped review and five root report updates plus per-feature status. No changes to notification demo origin authorized separately.
